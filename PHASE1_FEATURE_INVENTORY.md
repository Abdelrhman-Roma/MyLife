# PHASE 1 — FEATURE INVENTORY

## Summary

This inventory catalogs every user-facing feature of the legacy Momentum / MyLife vanilla-JS application across 17 domains, as the source of truth for the React migration.

- **Total domains:** 17 (AUTH, DASHBOARD, TODO, HABITS, GOALS, CALENDAR, WORKOUT, NUTRITION, PRAYER, STUDY, STATISTICS, WEATHER, ACCOUNT/SETTINGS, GAMIFICATION, NOTIFICATIONS, PWA/OFFLINE, I18N/LOCALIZATION).
- **Total discrete features cataloged:** ~150 (see per-domain matrices).
- **Implemented in React:** 0 of ~150. The `MyLife-React/` directory exists in the working tree (untracked) but no legacy feature has yet been ported. This document defines the target surface area.

### Architecture snapshot (legacy)

- Multi-page static app (one HTML file per domain), no SPA router. Navigation is plain `<a href="{page}.html">`; current page read from `document.body.dataset.page`.
- Shared shell (`shared.js`, ~105 KB): sidebar, topbar, page-art, stats strip, notification bell, theme/appearance, session gate, generic form/list/card renderers.
- Hybrid data layer:
  - **Fully migrated to Firestore per-module repositories:** Auth, Profile/Settings/Security, Todos, Dashboard layout, Gamification (XP/streaks/achievements/badges), Weather preferences, Notifications.
  - **Still on the legacy `window.currentData` blob** (synced whole via `LegacyDataSync.js` to `users/{uid}.appData`): Habits, Goals, Calendar, Workout, Prayer, Nutrition, Study, Water, Sleep. Repositories exist and are ready but are not yet the write path.
- Firebase project: `momentum-6bb1d`. Firestore uses `persistentLocalCache` + `persistentMultipleTabManager`.

### Known split-brain / defects to preserve-or-fix during migration

- Workout PLAN (schedule + exercise definitions) lives entirely in legacy `appData` → different plans per device.
- Prayer times are hardcoded static strings, not computed from location/date.
- Hadith section has no data (stub service always throws `NO_DATA`).
- Several dashboard snapshot widgets read wrong field shapes (Prayer, Workout, Water) → always show 0/undefined.
- Nutrition shopping-list buttons have malformed selectors (`data-nut-shop-generate"`) → never wire up.
- Multiple timer leaks on SPA-style navigation (workout session clock, study Pomodoro ticker, dashboard weather 30-min interval).

### Performance Bottlenecks

1. **`shared.js` (105 KB unminified)** — parsed and executed synchronously on every page load; contains all auth, navigation, UI rendering, and data logic for the entire app
2. **Full-page innerHTML re-render** — `todo.js`, `nutrition.js`, `habits.js`, and `goals.js` replace entire DOM trees on each Firestore snapshot instead of diffing; causes layout thrash and focus loss
3. **No code splitting** — legacy app has no build step; all JS loads unconditionally; React app has only 2 routes code-split so far
4. **No image lazy loading** — only `workout.js` progress photos use `IntersectionObserver`; all other images (dashboard backgrounds, space assets) load eagerly
5. **Three timer leaks on navigation** — workout session clock, study Pomodoro, and dashboard weather interval all persist across page transitions
6. **No memoization** — computed values (streak counts, macro totals, filter results, sorted lists) recalculated from scratch on every render cycle
7. **Firestore fan-out reads** — `RepoAggregatorSync` subscribes to all collections simultaneously on dashboard load; no lazy subscription by visible widget
8. **`window.currentData` global blob** — entire data state mirrored to a global object; stale data race conditions on rapid navigation

### Expected Final Architecture

A single React 18 + Vite 5 + TypeScript 5 SPA at `MyLife/` (or `MyLife/MyLife-React/` as working subdirectory until cutover). Full spec in `PHASE1_FINAL_ARCHITECTURE.md`.

Key properties:
- **Single source of truth:** Firestore for all domain data; localStorage only for UI preferences and read-only caches
- **One repository per collection:** 39 typed TypeScript repositories implementing `IRepository<T>`
- **One custom hook per feature:** `use{Domain}` hook owns the `onSnapshot` subscription, all write helpers, and loading/error state
- **No globals:** Zero `window.*` assignments; all services are ES module singletons
- **15 routes:** All code-split with `React.lazy`; protected by `ProtectedRoute` / `PublicRoute` guards
- **Strict TypeScript:** `strict: true` with all extra checks enabled
- **RTL-first:** CSS logical properties throughout; Arabic layout requires no overrides
- **Zero timer leaks:** Every interval/timeout stored in `useRef` and cleared in `useEffect` cleanup
- **Initial JS payload:** Under 80 KB (Firebase chunk loaded separately and cached)
